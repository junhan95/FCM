# FCM 관할별 법령 대응

> 상태: 초안 · 갱신 2026-08-26
>
> ⚠️ **저는 변호사가 아니며 이 문서는 법률 자문이 아닙니다.** 공개 자료를 근거로 설계에 반영해야 할 요건을 정리한 것이며, 실제 발송 개시 전 각 관할의 법률 검토가 필요합니다. 출처는 문서 말미에 있습니다.

## 1. 왜 이 문서가 필요한가

FCM 은 4개 관할에 걸친 5개 사업장에서 마케팅 이메일을 발송합니다.

| 코드 | 법인 | 소재 | 적용 법령 |
|---|---|---|---|
| FRH | Frankonia Germany EMC Solutions GmbH | Heideck, 독일 | **GDPR + UWG §7** |
| FRF | Frankonia EMC Test-Systems GmbH | Forchheim, 독일 | **GDPR + UWG §7** |
| FRJ | Frankonia (Jiashan) | Jiashan, 중국 | **PIPL** |
| FRK | Frankonia Korea EMC Solutions | 한국 | **개인정보보호법 + 정보통신망법** |
| FRI | Frankonia India EMC Solutions Pvt. Ltd. | 인도 | **DPDP Act 2023** |

요건이 관할마다 다르므로, **발송 규칙을 전역 상수로 두면 어느 한 곳은 반드시 위반**하게 됩니다. 사업장별 규칙 테이블이 필요합니다.

> 다행히 **완전 격리 구조가 여기서 유리하게 작용합니다.** 고객 데이터가 이미 `site_id` 로 분리되어 있으므로, 관할별 규칙을 사업장 단위로 적용하면 됩니다.

## 2. 관할별 요건

### 2-1. 독일 (FRH, FRF) — GDPR + UWG §7

**⚠️ 가장 중요한 발견: 독일은 B2B 마케팅 이메일에도 사전 동의가 필요합니다.**

"B2B 는 자유롭다"는 통념이 독일에는 통하지 않습니다. UWG §7(2)(2) 는 사전 명시적 동의 없는 마케팅 이메일을 부당한 괴롭힘으로 규정하며, **수신자가 개인이든 법인이든 동일하게 적용**됩니다. FRH 가 프로젝트를 주도하는 사업장이므로 이 조건이 기본 설계 기준이 되어야 합니다.

**예외 — Soft opt-in (UWG §7(3))**: 기존 고객에게는 동의 없이 발송 가능하나, **5개 조건을 모두** 충족해야 합니다.

1. 실제 계약 관계가 존재할 것 — 자료 요청 등 계약 전 접촉만으로는 불충분
2. 이메일 주소를 고객으로부터 **직접** 취득했을 것 (제3자 제공 불가)
3. 기존 구매 제품과 **유사한** 제품·서비스 광고에 한정
4. 수신자가 이의를 제기하지 않았을 것
5. **수집 시점과 매 발송 시마다** 거부권을 고지할 것

→ 시스템 요구: 동의 근거를 "명시적 동의"와 "거래관계 예외"로 구분해 기록해야 합니다. 후자는 위 조건 충족 여부를 입증할 수 있어야 합니다.

### 2-2. 한국 (FRK) — 정보통신망법

가장 구체적인 형식 요건을 요구하는 관할입니다.

| 요건 | 내용 | 시스템 대응 |
|---|---|---|
| 사전 동의 | 명시적 사전 동의 필수 | 동의 없으면 발송 차단 |
| **제목 표기** | 제목 **시작 부분**에 `(광고)` 표시. `(광 고)` `(광/고)` 등 변칙 표기 금지 | **발송 시 자동 삽입** |
| 야간 전송 | 21시~익일 08시 제한 — **이메일은 예외** | 이메일 전용이므로 해당 없음 |
| 수신거부 | 거부·철회를 쉽게 할 수 있는 조치 명시 + **수신자 비용 미부담** 고지 | 푸터 자동 삽입 |
| **동의 재확인** | **동의일로부터 2년마다** 확인. 전송자명·동의일자·철회방법 안내. 미응답 시 동의 지속 간주 | **만료 추적 및 자동 알림 필요** |
| 예외 | 거래관계로 직접 수집한 연락처에 거래 종료 후 **6개월 이내** 동종 재화 광고 | 근거·기한 추적 필요 |

**2년 재확인 의무가 시스템 기능을 요구합니다.** 사람이 엑셀로 관리할 수 없는 항목이며, FCM 이 해결해야 할 실질적 가치이기도 합니다.

### 2-3. 중국 (FRJ) — PIPL

쟁점은 발송 형식이 아니라 **국외 이전**입니다. FCM 서버를 독일이나 한국에 두면 중국 내에서 수집한 개인정보가 국경을 넘습니다.

2024년 CAC 규정 완화 이후 기준 (2026년 8월 현재):

| 구간 | 요건 |
|---|---|
| 비민감 개인정보 **10만 명 미만** | CAC 안전평가·표준계약 체결·인증 **모두 불필요** |
| 비민감 10만~100만 명 | 표준계약 체결 또는 인증 |
| 비민감 100만 명 초과 / 민감정보 1만 명 초과 / 중요데이터 | CAC 안전평가 필수 |

**FCM 의 FRJ 고객 규모는 B2B 영업 담당자 연락처이므로 10만 명에 크게 못 미칠 가능성이 높습니다.** 이 경우 국외 호스팅의 법적 장벽이 실질적으로 없습니다. 계약 이행·인사 관리 목적의 면제 조항도 별도로 존재합니다.

→ **확인 필요:** FRJ 의 실제 고객 연락처 건수, 그리고 해당 데이터가 "중요 데이터(重要数据)" 로 분류될 여지가 있는지. 전자는 세어보면 되고, 후자는 업종 특성상 낮아 보이나 확인이 필요합니다.

### 2-4. 인도 (FRI) — DPDP Act 2023

시행이 진행 중이며, **지금 설계하는 시스템은 처음부터 2027년 요건을 반영하는 것이 맞습니다.**

| 시점 | 상태 |
|---|---|
| 2026 중반 | Consent Manager 생태계 가동, 시스템 연동 준비 |
| **2026년 11월** | 전환기(soft enforcement) 종료, 능동적 규제 감독 시작 |
| 2027년 1분기 | 주요 데이터 수탁자 대상 독립 감사·DPIA 의무화 |
| **2027년 5월 13~14일** | **전면 시행** — 최대 25억 루피(약 2,600만 달러) 과징금 |

2026년은 "구축 및 시험의 해"로 규정됩니다. FCM 개발 시점과 정확히 겹치므로, 동의 관리·고지·이의제기 처리 구조를 지금 넣어두는 것이 나중에 얹는 것보다 훨씬 저렴합니다.

## 3. 설계에 미치는 영향

### 3-1. 동의는 단일 불리언이 될 수 없다

`consent = true/false` 로는 어느 관할도 충족하지 못합니다. 최소한 다음이 필요합니다.

- **근거 유형** — 명시적 동의 / 거래관계 예외(독일 soft opt-in) / 거래관계 예외(한국 6개월)
- **취득 시점** — 한국 2년 재확인, 한국 6개월 예외의 기산점
- **만료 시점** — 재확인 대상 산출
- **취득 경로** — 웹폼 / 전시회 명함 / 계약 / 기존 자료 이관
- **증빙** — 입증 책임 대응

### 3-2. 발송 규칙은 사업장별로 다르다

| 규칙 | FRH·FRF | FRK | FRJ | FRI |
|---|---|---|---|---|
| 제목 `(광고)` 자동 삽입 | 불필요 | **필수** | 불필요 | 불필요 |
| 동의 만료 재확인 | 불필요 | **2년** | 불필요 | 불필요 |
| 수신거부 푸터 | 필수 | 필수 (+비용 미부담 고지) | 필수 | 필수 |
| 사전 동의 | 필수 (B2B 포함) | 필수 | 필수 | 필수 |

→ `site` 테이블에 관할 코드를 두고 규칙을 파생시킵니다. 사업장 추가 시 규칙만 정의하면 되도록 합니다.

### 3-3. 기존 데이터 이관 시 동의 상태

**가장 위험한 지점입니다.** 현재 개인 스프레드시트에 있는 고객들은 동의 근거 기록이 없습니다. 이를 "동의함"으로 일괄 이관하면 **FCM 도입 명분(기획안 문제 #5, 통제되지 않은 발송의 법적 노출) 자체가 무너집니다.**

권장: 이관 시 전원 `unknown` 으로 두고, 재동의 캠페인 또는 거래관계 예외 근거 확인을 거쳐 개별 승격합니다. 초기에 발송 가능 대상이 크게 줄겠지만, 그것이 현재 실제 상태입니다.

### 3-4. 호스팅 위치

- 독일 호스팅: EU 데이터가 EU 내에 유지되어 GDPR 관점에서 가장 단순 → **Hetzner Cloud 독일 리전으로 확정 방향** (`07-기술스택.md` §4)
- 대량 발송도 EU 내 처리 — Amazon SES eu-central-1(프랑크푸르트) 권장
- 중국 데이터의 국외 이전: §2-3 기준 **면제 구간일 가능성이 높으나 건수 확인 필요**
- 한국·인도 데이터의 국외 이전: 각 법령상 고지·동의 요건 확인 필요

→ Michi 와 호스팅 협의 시 이 항목을 함께 검토해야 합니다.

## 5. 확인이 필요한 사항

1. **FRJ 고객 연락처 실제 건수** — 10만 명 미만이면 중국 국외 이전 규제가 실질적으로 해소됩니다
2. **각 사업장의 기존 고객 동의 근거 보유 여부** — 재동의 캠페인 규모를 결정합니다
3. FRI 를 1차 범위에 포함할 것인가 — 포함 시 2027년 5월 시한이 프로젝트 일정에 들어옵니다
4. ~~호스팅 위치~~ → 독일(Hetzner Cloud) 방향. 남은 것은 승인 (`07` §9)
5. 각 관할 법률 검토 주체 — 독일 본사 법무 활용 가능 여부
