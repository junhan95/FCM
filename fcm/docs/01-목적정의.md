## 1. 한 줄 정의

**Frankonia 그룹 4개 사업장의 고객 데이터를 단일 원천으로 통합하고, 통제된 이메일 발송과 영업 팔로업 추적을 제공하는 사내 자체 개발 웹 도구.**

## 2. 왜 필요한가 (기획안 "Why we need it")

| # | 문제 | 성격 |
|---|---|---|
| 1 | 고객 연락처가 4개 사업장의 개인 스프레드시트에 분산 — 단일 진실 원천 없음 | 데이터 |
| 2 | 같은 고객을 두 담당자가 서로 모른 채 중복 영업 | 프로세스 · **사업장 간은 수용** |
| 3 | 누구에게 무엇을 언제 보냈는지 기록 없음 | 추적성 |
| 4 | 퇴사 시 담당자의 연락처가 함께 소실 | 자산 손실 |
| 5 | 통제되지 않은 스프레드시트 기반 마케팅 발송 | **법적 리스크** — 4개 관할 적용 |

5번이 이 프로젝트에 마감 압박을 만드는 항목입니다. 기획안은 "legal exposure"라고만 서술하며, 구체적으로 어느 법령이 적용되는지는 각 사업장의 소재 국가가 확정되어야 판단할 수 있습니다(→ `04-사이트권한구조.md` §1). 다만 동의 근거 없이 마케팅 메일을 발송하는 상태는 어느 관할에서도 문제가 되므로, 법령 확정 전에도 동의 관리 설계는 선행되어야 합니다. `[도출]`

## 3. 무엇을 하는가 (기획안 "What it does")

- 스프레드시트 업로드 → 컬럼 정규화 → 중복 탐지
- 업로드 세션의 활성 사업장으로 고객 자동 귀속
- 수신자 수동 선택 또는 저장된 조건으로 필터링
- 텍스트·이미지·첨부·브로슈어를 포함한 메일 작성
- 회사 Outlook 계정 `sales@frankoniagroup.com` 을 통해 발송
- 모든 발송을 개별 고객 단위로 기록

## 4. 무엇을 보호하는가 (기획안 "What it protects")

- 각 사업장은 자기 고객만 조회 — **데이터베이스 레벨에서 강제** (완전 격리 확정)
- 연락처별 수신 동의 추적, 동의 없으면 자동 제외
- 최근 7일 내 연락한 대상에게 발송 시 경고
- 권한 3단계: Staff / Site Administrator / System Administrator

## 5. 추가 요구 (기획안 "What we need")

- **디지털 팔로업 테이블** — 상태/단계 또는 프로젝트, 수주 확률, 프로젝트별 피드백란
- **Forecast & Status 리포팅** — 팔로업 데이터를 근거로 산출
- **국가별 고객 DB** — 뉴스레터, 초청장 등 후속 활용

## 6. 규모와 범위

- 사용자: 여러 부서에 걸쳐 10명 이상
- 사업장: **FRH**(Heideck, 독일) · **FRF**(Forchheim, 독일) · **FRJ**(Jiashan, 중국) · **FRK**(한국) · **FRI**(인도)
- **관할 4개** — EU/독일, 중국, 한국, 인도. 발송 규칙과 동의 요건이 사업장마다 다름 (→ `06-관할별법령대응.md`)
- 주도: FRH / 참여 검토: FRF, FRJ, FRI
- 확장 목표: Frankonia 하위 조직(FRJ, FRI, FRF)에서도 사용 가능한 도구

## 6-A. 접근 통제 원칙 (최우선)

각 사업장의 영업담당자가 자기 사업장 고객만 관리하는 구조이며, 이는 이 프로젝트에서 가장 중요한 요구입니다.

- 인가된 영업담당자만 접속 가능 — 자가 가입 없음
- 초기 화면은 **로그인 화면**
- 로그인은 **ID + 비밀번호 + 사업장 선택** 세 요소
- 로그인 이후 해당 사업장 환경만 노출 — **사업장 전환은 재로그인**
- **주소를 직접 입력해도 타 사업장 데이터에 접근할 수 없음**
- 겸직 가능 `[확정]` — 관리자가 사업장별로 권한을 부여하며, 역할도 사업장별로 다를 수 있음

> 사업장 간 중복 영업은 이 격리 구조의 결과로 **수용**합니다. 기획안 문제 #2 는 사업장 내부에 한정해 대응합니다.

상세 설계: `05-인증접근제어.md`

## 7. 구현 방향

- **형태:** AI를 활용한 사내 자체 개발 웹 애플리케이션
- **스택:** Next.js + TypeScript · PostgreSQL · Docker Compose (→ `07-기술스택.md`)
- **저장소:** github.com/junhan95/FCM
- **호스팅:** MVP 까지 junhan 관리 Hetzner Cloud VPS → **MVP 완성 후 본사 서버 이관**
- **발송:** 하이브리드 — 개별은 Outlook Graph API, 대량은 전용 서비스 + 서브도메인
- **활용 가능 자산 `[도출]`:** CyberShield 구축 시 마련한 SFTP 배포 파이프라인 및 호스팅 서버. 단 CyberShield는 MySQL 기반이며, FCM의 DB 레벨 격리 요구를 충족하려면 DB 선택을 별도 검토해야 함 (→ `03-데이터모델초안.md` §6-2)
